Cette section décrit la gestion des environnements pour l'intégration de l'API EASYTRANSFERT BUSINESS, en s'appuyant sur l'implémentation réelle fournie via la collection et l'environnement Testeur d'API.

## Environnement actif

À l'état actuel, l'API EASYTRANSFERT expose un seul environnement actif accessible via l'URL suivante :

```
http://proxy-airtime.easytransfert.app/api_v1/transaction
```

**Cet environnement est utilisé :**

- pour les tests d'intégration
- pour les transactions en conditions réelles
- pour la validation fonctionnelle des flux Cashin / Cashout

<Info>
  La différenciation des usages (test ou production) repose sur la clé API (api_key) fournie par EASYTRANSFERT et sur les droits qui lui sont associés.
</Info>

## Tests et production

Les tests et les transactions en production utilisent le même environnement. La différenciation se fait uniquement via les clés API.

<Warning>
  Il est fortement déconseillé d'effectuer des tests non contrôlés avec une clé API de production.
</Warning>

## Gestion des environnements via les clés API

La gestion des environnements repose sur le mécanisme suivant :

- Chaque partenaire reçoit une ou plusieurs clés API
- Les clés API sont configurées côté EASYTRANSFERT avec :
  - des plafonds
  - des services autorisés
  - des restrictions éventuelles
- Le comportement de l'API dépend directement de la clé utilisée

**Ainsi :**

- une clé peut être dédiée aux tests
- une autre clé à la production
- sans changement d'URL ni de structure de requête

## Configuration recommandée

### Dans Testeur d'API

- Une collection unique
- Un ou plusieurs environnements Testeur d'API
- Variables clés :
  - `base_url`
  - `api_key`
  - `ipn_url`
  - `service_id_*`

### Dans une application

- Utiliser des fichiers de configuration (.env, variables système)
- Ne jamais stocker la clé API en dur dans le code
- Séparer clairement les clés API :
  - clé API pour les tests
  - clé API pour la production
