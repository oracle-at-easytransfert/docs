---
title: "Création de transaction"
description: "Comment créer et initier une transaction Cashin ou Cashout"

---

La création d'une transaction permet d'initier un Cashin (ajout d'argent) ou un Cashout (retrait) sur le compte mobile money du client via l'API EASYTRANSFERT.

## Endpoint principal

```
POST {{base_url}}/airtime
```

## Headers

```
Content-Type: application/json
```

## Body JSON

```json
{
    "amount": 1000,
    "api_key": "{{api_key}}",
    "destination": "0670123456",
    "service_id": {{service_id_mtn_cashin}},
    "ipn_url": "{{ipn_url}}",
    "custom_data": "identifiant_unique_transaction"
}
```

## Description des paramètres

| Paramètre | Type | Obligatoire | Description |
|-----------|------|-------------|-------------|
| `amount` | int | Oui | Montant de la transaction en FCFA. Doit être un entier positif. |
| `api_key` | string | Oui | Clé API EASYTRANSFERT valide pour authentification. |
| `destination` | string | Oui | Numéro du bénéficiaire au format local (ex: 0670123456). |
| `service_id` | int | Oui | Identifiant du service correspondant au type de transaction (Cashin / Cashout). |
| `ipn_url` | string | Non | URL pour recevoir la notification IPN (optionnelle, mais recommandée). |
| `custom_data` | string | Non | Données personnalisées pour identifier la transaction (optionnel). |

<Tip>
  Le champ `custom_data` est très utile pour faire le lien entre la transaction EASYTRANSFERT et votre système interne (ID commande, référence facture, etc.).
</Tip>

## Réponse immédiate

<Warning>
  La réponse immédiate ne confirme **pas** le succès final de la transaction. Elle indique seulement que la requête a été reçue et acceptée.
</Warning>

**Exemple de réponse :**

```json
{
  "status": "success",
  "data": {
    "transaction_id": "EFB.001158"
  }
}
```

<Info>
  Le `transaction_id` doit être sauvegardé côté application. Il sera utilisé pour :
  - Faire le lien avec la notification IPN
  - Consulter le statut si nécessaire
  - Le rapprochement comptable
</Info>

## Confirmation finale

La confirmation finale du statut de la transaction (SUCCESS ou FAILED) est envoyée via :

- **IPN (Webhook)** : Mécanisme recommandé, notification automatique
- **Endpoint /status** : Consultation ponctuelle uniquement en cas de besoin

<Tip>
  Privilégiez toujours le mécanisme IPN pour connaître le statut final. L'endpoint /status doit être utilisé uniquement en cas de non-réception d'IPN.
</Tip>
