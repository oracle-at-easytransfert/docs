L'API EASYTRANSFERT BUSINESS – v1 est conçue pour répondre à des besoins concrets de paiements Mobile Money automatisés, aussi bien pour des flux entrants (Cashin) que sortants (Cashout).

<Info>
  Les cas d'usage ci-dessous correspondent exclusivement aux fonctionnalités réellement disponibles dans l'API v1.
</Info>

## Intégration dans une application métier

L'API peut être intégrée dans :

- Applications web
- Applications mobiles
- Back-offices de gestion
- Plateformes SaaS

**Exemples :**

- Un tableau de bord interne permettant d'initier des paiements Mobile Money
- Une application mobile déclenchant des cashouts vers les utilisateurs finaux
- Un système ERP déclenchant automatiquement des paiements après validation métier

**L'intégration se fait via :**

- Requêtes HTTP POST
- Format JSON
- Authentification par clé API

## Paiements B2B / B2C

<AccordionGroup>
  <Accordion title="Paiements B2C (Cashout)" icon="arrow-down">
    Décaissement de fonds vers des clients finaux via Mobile Money.
    
    **Cas typiques :**
    - Paiement de commissions
    - Paiement de prestataires
    - Remboursements clients
    - Paiement de salaires ou primes
    
    **Processus :**
    1. Initiation de la transaction Cashout
    2. Traitement par l'opérateur Mobile Money
    3. Notification du résultat via IPN
  </Accordion>
  
  <Accordion title="Paiements B2B (Cashin / Cashout)" icon="exchange-alt">
    Encaissement ou décaissement entre entreprises ou partenaires.
    
    **Exemples :**
    - Encaissement de paiements partenaires (Cashin)
    - Décaissement vers des comptes professionnels Mobile Money
    - Gestion de flux financiers inter-entreprises
  </Accordion>
</AccordionGroup>

## Centralisation des flux Mobile Money

L'API permet de centraliser plusieurs opérateurs Mobile Money derrière une interface unique :

- MTN Mobile Money
- Orange Money
- Moov Money
- Flooz

<Info>
  Grâce au paramètre `service_id` :
  - l'intégration reste identique
  - seul l'opérateur change
</Info>

**Cela permet :**

- une maintenance simplifiée
- une évolutivité sans refonte technique
- une homogénéisation des flux de paiement

## Suivi et reporting des transactions

L'API fournit deux mécanismes complémentaires pour le suivi :

<CardGroup cols={2}>
  <Card title="Suivi asynchrone (IPN - recommandé)" icon="webhook" color="#1d60d5">
    - Réception automatique du statut final
    - Aucun polling intensif nécessaire
    - Statuts possibles : **SUCCESS** ou **FAILED**
    
    <Tip>
      Ce mécanisme est le canal principal de confirmation des transactions.
    </Tip>
  </Card>
  
  <Card title="Suivi ponctuel (endpoint statut)" icon="search" color="#1d60d5">
    - Consultation du statut via transaction_id
    - À utiliser uniquement en cas de :
      - non-réception d'IPN
      - besoin exceptionnel de vérification
    
    <Warning>
      L'interrogation répétée du statut est déconseillée et peut entraîner un blocage.
    </Warning>
  </Card>
</CardGroup>

## Traçabilité et rapprochement métier

L'API permet une traçabilité efficace via :

- **transaction_id** : identifiant unique EASYTRANSFERT
- **custom_data** : référence métier libre fournie par le partenaire
- **timestamps** : de création et de mise à jour (IPN)

**Cela facilite :**

- le rapprochement comptable
- l'audit des transactions
- le support client

<Warning>
  **Cas NON couverts par l'API v1**
  
  Pour éviter toute ambiguïté, les cas suivants ne sont pas supportés dans la version actuelle :
  - Gestion des clients ou utilisateurs
  - Gestion des bénéficiaires persistés
  - Consultation de solde ou de wallet business
  - Annulation ou remboursement de transaction via API
</Warning>
