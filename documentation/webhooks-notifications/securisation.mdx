L'IPN est un point critique de sécurité, car il reçoit automatiquement des notifications de transactions et peut déclencher des actions financières dans votre système. Il est donc essentiel de sécuriser correctement votre endpoint.

## Objectifs de la sécurisation

## Méthodes de sécurisation recommandées

| Méthode | Description | Mise en œuvre |
|---------|-------------|---------------|
| **HTTPS obligatoire** | Toutes les IPN doivent utiliser HTTPS en production pour protéger les données en transit. | Certificat SSL valide pour votre ipn_url. |
| **Validation IP / Réseau** | Filtrer les requêtes entrantes selon les plages IP d'EASYTRANSFERT si fournies. | Firewall ou règles réseau. |
| **Token secret ou signature** | EASYTRANSFERT peut envoyer un token ou une signature HMAC dans les headers pour authentifier la requête. | Comparer le token/signature reçu avec celui attendu dans votre système. |
| **Vérification de payload** | Vérifier que transaction_id, amount et service_id correspondent à vos enregistrements. | Requête dans votre base de données pour confirmer la transaction. |
| **Idempotence** | Traiter chaque transaction_id une seule fois, même si l'IPN est reçu plusieurs fois. | Marquer chaque transaction comme "traitée" après le premier succès. |
| **Logs et audit** | Enregistrer toutes les IPN reçues avec date/heure pour audit et traçabilité. | Base de données ou fichier de logs sécurisé. |

## Exemple concret de sécurisation HMAC

EASYTRANSFERT peut envoyer un header `X-EASYTRANSFERT-SIGNATURE` (exemple) généré avec un secret partagé.

**Exemple en pseudo-code (Node.js / Express) :**

```javascript
const crypto = require('crypto');

app.post('/webhook/easytransfert', (req, res) => {
    const secret = process.env.EASYTRANSFERT_SECRET;
    const payload = JSON.stringify(req.body);
    const signature = req.headers['x-easytransfert-signature'];

    const hash = crypto.createHmac('sha256', secret)
                       .update(payload)
                       .digest('hex');

    if (hash !== signature) {
        console.log("IPN non authentifié");
        return res.status(403).send("Forbidden");
    }

    // Traitement du payload sécurisé
    const transactionId = req.body.transaction_id;
    // ... mettre à jour la base de données, notifier l'utilisateur, etc.

    res.status(200).send('OK'); // Confirme la réception
});
```

## Bonnes pratiques supplémentaires

<CardGroup cols={2}>
  <Card title="Limiter les tentatives" icon="ban">
    Détecter les IPN répétées avec le même transaction_id.
  </Card>
  <Card title="Timeout rapide" icon="clock">
    Répondre à EASYTRANSFERT rapidement pour éviter les ré-envois.
  </Card>
  <Card title="Notification d'échec" icon="exclamation-triangle">
    Logger toute tentative non authentifiée pour audit.
  </Card>
  <Card title="Tests en sandbox" icon="flask">
    Avant production, tester toutes les IPN avec votre ipn_url sandbox.
  </Card>
</CardGroup>

<Info>
  **Compatibilité avec Testeur d'API / Environment :**
  - La variable {{ipn_url}} dans votre environment permet de basculer facilement entre sandbox et production.
  - Les exemples IPN (SUCCESS et FAILED) peuvent être envoyés via Testeur d'API pour tester la sécurisation avant mise en production.
