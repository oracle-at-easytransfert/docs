L'API EASYTRANSFERT envoie des notifications IPN pour les événements suivants :

## Événements de transaction

<CardGroup cols={2}>
  <Card title="Transaction SUCCESS" icon="check-circle" color="#16a34a">
    Notification envoyée lorsqu'une transaction est finalisée avec succès.
    
    **Champs principaux :**
    - `state`: "SUCCESS"
    - `reponse`: Message de confirmation
    - `amount`: Montant de la transaction
  </Card>
  
  <Card title="Transaction FAILED" icon="times-circle" color="#dc2626">
    Notification envoyée lorsqu'une transaction échoue.
    
    **Champs principaux :**
    - `state`: "FAILED"
    - `error`: Message d'erreur détaillé
    - `amount`: Montant de la transaction
  </Card>
</CardGroup>

## Structure du payload IPN

Toutes les notifications IPN contiennent les champs suivants :

| Champ | Type | Description | Présent si |
|-------|------|-------------|------------|
| `transaction_id` | string | Identifiant unique de la transaction | Toujours |
| `state` | string | État de la transaction (SUCCESS ou FAILED) | Toujours |
| `amount` | number | Montant de la transaction en FCFA | Toujours |
| `reponse` | string | Message de succès | Si SUCCESS |
| `error` | string | Message d'erreur | Si FAILED |
| `custom_data` | string | Données personnalisées envoyées à l'initiation | Si fourni |
| `service_id` | number | Identifiant du service utilisé | Toujours |
| `destination` | string | Numéro du bénéficiaire | Toujours |
| `created_at` | string | Date de création de la transaction | Toujours |
| `updated_at` | string | Date de dernière mise à jour | Toujours |

## Exemple d'événement SUCCESS

```json
{
    "transaction_id": "EFB.144358",
    "state": "SUCCESS",
    "amount": 1000,
    "reponse": "operation succes",
    "error": "",
    "custom_data": "transaction_ref_001",
    "service_id": 14,
    "destination": "0500156008",
    "created_at": "2022-10-18T02:38:44.000+00:00",
    "updated_at": "2022-10-18T02:38:44.000+00:00"
}
```

## Exemple d'événement FAILED

```json
{
    "transaction_id": "EFB.144359",
    "state": "FAILED",
    "amount": 2000,
    "reponse": "",
    "error": "Solde insuffisant",
    "custom_data": "transaction_ref_123",
    "service_id": 10,
    "destination": "0670123456",
    "created_at": "2022-10-18T02:38:44.000+00:00",
    "updated_at": "2022-10-18T02:38:44.000+00:00"
}
```

## Bonnes pratiques

<CardGroup cols={2}>
  <Card title="Traiter tous les événements" icon="check-double">
    Votre endpoint doit être capable de traiter à la fois les événements SUCCESS et FAILED.
  </Card>
  <Card title="Vérifier le state" icon="search">
    Toujours vérifier le champ state pour déterminer le type d'événement reçu.
  </Card>
  <Card title="Gérer les doublons" icon="redo">
    Un même événement peut être envoyé plusieurs fois. Assurez-vous de gérer l'idempotence.
  </Card>
  <Card title="Logger tous les événements" icon="file-alt">
    Enregistrez tous les événements reçus pour audit et traçabilité.
  </Card>
</CardGroup>

<Info>
  Les notifications IPN sont envoyées de manière asynchrone. Il est possible qu'un événement SUCCESS ou FAILED soit envoyé plusieurs fois pour garantir la livraison.
</Info>

<Tip>
  Assurez-vous que votre endpoint IPN peut gérer tous les types d'événements pour garantir une intégration robuste.
</Tip>
