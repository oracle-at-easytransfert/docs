Cette section permet aux développeurs de comprendre les étapes du fonctionnement des APIs, en s'appuyant directement sur la collection [Testeur d'API officielle EASYTRANSFERT](/api-reference/endpoint/transaction).

## Le cycle de vie d'une transaction

Le cycle de vie d'une transaction EASYTRANSFERT se fait en 3 étapes clés :

<Steps>
  <Step title="Initiation d'une transaction" stepNumber={1}>
    Envoi d'une requête POST pour initier une transaction Cashin ou Cashout
  </Step>
  <Step title="Réception de la notification IPN" stepNumber={2}>
    Réception automatique du statut final (SUCCESSFUL ou FAILED) via webhook
  </Step>
  <Step title="Consultation ponctuelle du statut (optionnel)" stepNumber={3}>
    Vérification manuelle du statut uniquement en cas de besoin
  </Step>
</Steps>

## Flux visuel

```
[Votre système]
      |
      | POST /airtime
      v
[EASYTRANSFERT]
      |
      | IPN (SUCCESSFUL / FAILED)
      v
[Votre webhook]
```

## Points clés à retenir

<CardGroup cols={2}>
  <Card title="Authentification par clé API" icon="key">
    L'authentification se fait via la clé API transmise dans le corps de la requête (body JSON).
  </Card>
  <Card title="Une transaction = une requête" icon="exchange-alt">
    Chaque transaction nécessite un appel unique à l'endpoint /airtime.
  </Card>
  <Card title="IPN = confirmation officielle" icon="check-circle">
    La notification IPN confirme le statut final de la transaction.
  </Card>
  <Card title="/status = secours uniquement" icon="life-ring">
    L'endpoint /status doit être utilisé uniquement en cas de non-réception d'IPN.
  </Card>
</CardGroup>
