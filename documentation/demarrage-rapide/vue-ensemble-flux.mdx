Cette section permet à un développeur d'effectuer sa première transaction fonctionnelle en moins de 10 minutes, en s'appuyant directement sur la collection Testeur d'API officielle EASYTRANSFERT.

## Le cycle de vie d'une transaction

Le cycle de vie d'une transaction EASYTRANSFERT se fait en 4 étapes clés :

<Steps>
  <Step title="Préparation de l'environnement">
    Configuration des variables d'environnement (base_url, api_key, ipn_url, service_id)
  </Step>
  <Step title="Initiation d'une transaction">
    Envoi d'une requête POST pour initier une transaction Cashin ou Cashout
  </Step>
  <Step title="Réception de la notification IPN">
    Réception automatique du statut final (SUCCESS ou FAILED) via webhook
  </Step>
  <Step title="Consultation ponctuelle du statut (optionnel)">
    Vérification manuelle du statut uniquement en cas de besoin
  </Step>
</Steps>

<Warning>
  **Important :** Il n'existe pas de gestion de clients (customers) dans cette version de l'API. L'identification se fait uniquement via la clé API (api_key).
</Warning>

## Flux visuel

```
[Votre système]
      |
      | POST /airtime
      v
[EASYTRANSFERT]
      |
      | IPN (SUCCESS / FAILED)
      v
[Votre webhook]
```

## Points clés à retenir

<CardGroup cols={2}>
  <Card title="Pas de création client" icon="user-slash">
    L'API ne gère pas les clients. L'authentification se fait uniquement via la clé API.
  </Card>
  <Card title="Authentification par api_key" icon="key">
    La clé API est transmise dans le corps de la requête (body JSON).
  </Card>
  <Card title="Une transaction = une requête" icon="exchange-alt">
    Chaque transaction nécessite un appel unique à l'endpoint /airtime.
  </Card>
  <Card title="IPN = confirmation officielle" icon="check-circle">
    La notification IPN est la source de vérité pour le statut final de la transaction.
  </Card>
  <Card title="/status = secours uniquement" icon="life-ring">
    L'endpoint /status doit être utilisé uniquement en cas de non-réception d'IPN.
  </Card>
</CardGroup>
