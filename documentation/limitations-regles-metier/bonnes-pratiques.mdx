Cette section résume les règles métier transversales et les pratiques recommandées pour garantir la fiabilité des transactions.

## Principes

<CardGroup cols={2}>
  <Card title="Automatisation intelligente" icon="cog" color="#1d60d5">
    Préférez l'automatisation via API tout en respectant le rate limit et les restrictions géographiques.
  </Card>
  <Card title="Sécurité" icon="shield" color="#16a34a">
    Ne partagez jamais vos clés API. Utilisez HTTPS pour toutes les requêtes.
  </Card>
  <Card title="Gestion des erreurs" icon="exclamation-triangle" color="#dc2626">
    Implémentez un suivi systématique des transactions FAILED et des codes HTTP (429, 400, 500).
  </Card>
  <Card title="Surveillance et reporting" icon="chart-line">
    Centralisez les logs des transactions et des IPN pour audit et suivi. Conservez les informations de transaction_id, custom_data, et state.
  </Card>
</CardGroup>

## Bonnes pratiques concrètes

### 1. Webhook IPN obligatoire

<Card title="IPN = source de vérité" icon="webhook" color="#1d60d5">
  Ne comptez pas uniquement sur les réponses immédiates de l'API. L'IPN est la source principale pour confirmer le succès ou l'échec d'une transaction.
</Card>

### 2. Validation côté client

<CardGroup cols={2}>
  <Card title="Numéro valide" icon="phone">
    Numéro du bénéficiaire valide
  </Card>
  <Card title="Montant dans les limites" icon="chart-line">
    Montant dans les limites
  </Card>
  <Card title="Service ID correct" icon="cog">
    Service ID correct
  </Card>
  <Card title="Devise = FCFA" icon="money-bill">
    Devise = FCFA
  </Card>
</CardGroup>

### 3. Gestion des limites et plafonds

<CardGroup cols={2}>
  <Card title="Fractionner les transactions" icon="cut">
    Implémentez une logique interne pour fractionner les transactions si nécessaire.
  </Card>
  <Card title="Respecter les restrictions" icon="hand-raised">
    Respectez les restrictions géographiques et les limites par type de transaction.
  </Card>
</CardGroup>

### 4. Retry & backoff

<Card title="Attente progressive" icon="clock">
  Pour les erreurs temporaires (429 Too Many Requests, 500 Internal Server Error), utilisez une attente progressive avant de réessayer.
</Card>

## Résumé pratique

<AccordionGroup>
  <Accordion title="Suivre les webhooks IPN" icon="webhook">
    Suivre les webhooks IPN pour toutes les transactions.
  </Accordion>
  
  <Accordion title="Vérifier avant envoi" icon="check-circle">
    Vérifier montants, devises, numéro bénéficiaire, service ID avant envoi.
  </Accordion>
  
  <Accordion title="Fractionner si nécessaire" icon="cut">
    Fractionner les transactions trop grandes.
  </Accordion>
  
  <Accordion title="Respecter les limites" icon="hand-raised">
    Respecter le rate limit et les restrictions géographiques.
  </Accordion>
  
  <Accordion title="Conserver un historique" icon="file-alt">
    Conserver un historique centralisé pour audit et support.
  </Accordion>
</AccordionGroup>
